# แผน: เอาข้อด้อยของทุกระบบ มาเป็นจุดแข็งของ CameraSync

> อัปเดต 18 ต.ค. 2026 · หลักฐานจาก reverse engineering แบบ passive ของเว็บจริงทั้ง 3 เจ้า
> (ทำผ่าน `rea-agents` บน JS bundle/HTML สาธารณะ — รายงานเต็มใน [docs/rea/](rea/)) และการ
> research ตลาดใน [RESEARCH.md](RESEARCH.md)

## หลักการของเรา (ตรงข้ามกับทุกเจ้า)

1. **ดิสก์เครื่องช่างภาพคือที่เก็บหลัก** — เซิร์ฟเวอร์รันบนเครื่องช่างภาพ/สตูดิโอเอง
   เปิดไว้ตลอด ไม่มีวันหมดอายุ ไม่มีการย่อไฟล์ทิ้ง ไม่ต้องเช่าพื้นที่คลาวด์
2. คนนอกเข้าถึงได้ผ่าน **tunnel ในตัว** (`wedsync-server relay` + `wedsync tunnel`) หรือ VPN
   ส่วนตัว (Tailscale/ZeroTier) — รูปยังอยู่เครื่องเรา ไม่มีการ copy ขึ้นคลาวด์รายวัน
3. ครั้งแรกที่รัน = ผู้ใช้ตั้ง **user/pass ของตัวเอง** (ไม่มีบัญชี default ใด ๆ)

## สรุปการเรียนรู้เชิงเทคนิคจาก bundle คู่แข่ง

- Wedibox ใช้ javascript-obfuscator ครอบทั้ง bundle (string pool + `_0x`) — เขารักษาโค้ดแน่นหนา
  เราไม่ต้องทำเพราะ self-hosted โอเพนอยู่แล้ว และนั่นคือ selling point
- GuestPix แยกเว็บขาย (WordPress) กับแอปจริง (Vue SPA ที่ `my.guestpix.com`) — เรารวมอันเดียวจบ
- Memzo เป็น PHP server-rendered — หน้าแขกของเราเป็น SPA ครั้งเดียว เบากว่าบนมือถือ
